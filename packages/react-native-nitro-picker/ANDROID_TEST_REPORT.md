## 滚动开销优化复测

- 背面选项返回固定的透明矩阵样式，跳过三角函数和重复原生属性提交；平面模式也复用同一矩阵。
- Android 额外挂载范围按实际圆柱半径计算，从 `height * π / 2` 改为 `max(itemHeight, height / 2) * π / 2`，保留曲面所需行；原生惯性和吸附行为不变。
- 优化后增量构建成功（28 秒），重新安装。8 项 Node 测试、TypeScript、ESLint 通过；UIAutomator 两项测试通过，双指结果 `[4, 2]`；快速甩动后 `[4, 7]`，选项居中、曲面及图文显示正常。
- 开发包单轮 `dumpsys gfxinfo` 采样：从末项开始，左列交替执行 `(290,1240) → (290,930)` 及反向、每次 350ms，共 6 轮。修改前 264 帧、49 慢帧（18.56%），P50/P95 为 14/20ms；修改后 284 帧、37 慢帧（13.03%），P50/P95 为 13/18ms。启动及页面切换不包含在采样范围内。
- 该采样包含开发环境开销，帧数不同，且仅一次前后对比，不能作为稳定的性能收益或发布包验收结论。尚未进行 release 性能测试和 iOS 运行验证。

优化后采样、双指回归输出及截图保存在 `tests/artifacts/android-20261010/smooth-*`。

## RecyclerView 回收异常修复复测

2026-10-10：用户报告 `Scrapped or attached views may not be recycled`。设备历史日志中存在多次相同异常，堆栈均从延迟的 `layoutWork → layoutRows` 进入 RecyclerView 布局清理，其中部分日志紧跟窗口移除。修复前在当前会话重复内容重排和 Reload，未稳定复现；历史堆栈已保留，不能据此认定所有触发条件已查清。

- 针对脱离窗口后仍执行延迟布局的路径，Android 容器仅在已挂载时排队及执行布局；脱离窗口取消待执行任务与滚动，重新挂载时请求布局。没有捕获或吞掉 RecyclerView 异常，没有关闭回收机制。
- 可见终端增量构建成功（44 秒），APK 安装成功。新增两项实际设备回归：连续卸载/挂载 5 次、内容重排后 Surface Reload 3 次；与双指滚动、辅助功能增减一起执行，结果 `OK (4 tests)`。
- 测试前后 PID 均为 24838，该 PID 的 crash buffer 没有新增异常。额外检查“滚动开始即卸载”：列节点消失，重新挂载后选中值 `[4, 2]` 保持且图文居中，本轮没有再出现回收崩溃。
- 11 项 Node 回归测试、TypeScript 和 ESLint 通过；此验证只覆盖该设备和上述路径，iOS 未涉及原生修改，也未运行验证。

原始堆栈、修复后回归输出及截图见 `tests/artifacts/android-20261010/recycle-*`。
